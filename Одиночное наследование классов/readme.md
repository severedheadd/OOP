## Описание предметной области

В рамках выпускной квалификационной работы «Разработка системы управления гостиницей» рассматривается автоматизация учёта гостиничных номеров и управление их основными характеристиками.

Каждый номер имеет общие параметры: номер комнаты, этаж, количество мест и стоимость проживания за сутки. При этом номера могут отличаться по категории и предоставляемым удобствам.

Для реализации данной предметной области используется механизм одиночного наследования. В качестве базового класса создан `Room`, который содержит общие характеристики гостиничного номера. На его основе реализованы три производных класса: `StandardRoom` (стандартный номер), `LuxuryRoom` (номер категории «Люкс») и `FamilyRoom` (семейный номер).

## Реализация

Программа реализована на языке C++ с использованием принципов объектно-ориентированного программирования.

В базовом классе `Room` определены поля `roomNumber`, `floor`, `capacity` и `pricePerNight`, предназначенные для хранения номера комнаты, этажа, вместимости и стоимости проживания за сутки. Для инициализации этих характеристик используется конструктор. Также базовый класс содержит метод `displayInfo()` для отображения информации о номере и метод `calculateCost(int days)` для расчёта стоимости проживания за заданное количество суток.

Производные классы наследуют общие свойства и методы класса `Room` и дополняют их собственными характеристиками:

- `StandardRoom` — содержит дополнительное поле `hasTV`, указывающее на наличие телевизора.
- `LuxuryRoom` — содержит поле `hasJacuzzi`, определяющее наличие джакузи.
- `FamilyRoom` — содержит поле `hasKitchen`, указывающее на наличие кухни.

В каждом производном классе реализован собственный конструктор, который инициализирует унаследованные поля через конструктор базового класса и задаёт дополнительные характеристики соответствующего номера.

Метод `displayInfo()` переопределён с использованием `override`. При его вызове сначала отображаются общие характеристики номера с помощью `Room::displayInfo()`, а затем выводятся дополнительные сведения, характерные для конкретной категории.

Метод `calculateCost()` используется для расчёта общей стоимости проживания. Расчёт выполняется путём умножения стоимости одних суток на количество дней проживания. Благодаря размещению этого метода в базовом классе одинаковая логика не дублируется в производных классах.

В функции `main()` создаются объекты классов `StandardRoom`, `LuxuryRoom` и `FamilyRoom`. Для каждого объекта вызывается метод вывода информации, после чего рассчитывается стоимость проживания за три суток. Это позволяет проверить работу конструкторов, наследование общих характеристик и переопределение методов.

Таким образом, программа демонстрирует одиночное наследование: каждый производный класс имеет только один непосредственный базовый класс — `Room`.

Исходный код программы находится в файле [`main.cpp`](main.cpp).

## Удобство, гибкость и перспективы

Использование одиночного наследования позволяет повторно использовать общий код и уменьшить дублирование характеристик гостиничных номеров. Основные поля и методы сосредоточены в базовом классе, поэтому изменение общей логики работы с номерами не требует внесения одинаковых изменений во все производные классы.

Гибкость решения заключается в возможности расширения системы новыми категориями номеров. Например, можно добавить класс `BusinessRoom` для деловых путешественников или `AccessibleRoom` для номеров, оборудованных для маломобильных гостей. При этом существующие классы могут продолжать использовать общую функциональность `Room`.

Виртуальные методы также позволяют организовать полиморфную обработку различных категорий номеров через общий базовый класс. Это может быть полезно при формировании списка всех номеров гостиницы и отображении их характеристик независимо от конкретного типа объекта.

В дальнейшем проект можно развить до полноценной системы управления гостиницей, добавив регистрацию гостей, бронирование номеров, проверку доступности на выбранные даты, учёт дополнительных услуг и автоматический расчёт стоимости проживания с учётом скидок. Дополнительно можно реализовать подключение базы данных, графический интерфейс для сотрудников и формирование отчётов о загрузке гостиницы и выручке.

При расширении системы целесообразно разделить работу с номерами, бронированиями и данными гостей на отдельные компоненты. Это позволит упростить сопровождение программы и обеспечить возможность дальнейшего развития без существенного изменения существующей структуры классов.
